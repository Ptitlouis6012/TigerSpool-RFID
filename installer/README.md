# Web installer

> **Status: not implemented.** The design is here; the page and the manifest are
> not written yet.

Flash a TigerSpool from a browser. Plug the board into a computer, open the page,
click **Install**. No PlatformIO, no Arduino IDE, no command line, no drivers to
hunt down.

Built on [ESP Web Tools](https://esphome.github.io/esp-web-tools/), which speaks
WebSerial. **Chrome and Edge on a desktop OS only** — Safari and Firefox do not
implement WebSerial, and no mobile browser does. The page has to say so plainly
rather than failing silently.

## How it will work

```
   browser                              GitHub Pages
      |                                      |
      |--- GET manifest.json --------------->|
      |<-- version + parts list              |
      |                                      |
      |--- GET the .bin files -------------->|
      |<== bootloader, partitions, app, fs ==|
      |                                      |
  [ user picks the serial port ]             |
  [ esptool.js writes over WebSerial ]       |
  [ board reboots into TigerSpool ]          |
```

Published to GitHub Pages by CI on every tagged release. **Binaries are never
committed to this repository** — they are built by the release workflow and
deployed with the page, so the installer and the OTA channel always offer the same
build. See [../docs/OTA.md](../docs/OTA.md).

## `manifest.json`

Generated by CI from the firmware's own version macro. Never hand-edited —
hand-editing is how an installer and an OTA channel drift apart.

```json
{
  "name": "TigerSpool RFID",
  "version": "1.0.0",
  "home_assistant_domain": null,
  "new_install_prompt_erase": true,
  "builds": [
    {
      "chipFamily": "ESP32-S3",
      "parts": [
        { "path": "firmware/bootloader.bin",            "offset": 0 },
        { "path": "firmware/partitions.bin",            "offset": 32768 },
        { "path": "firmware/boot_app0.bin",             "offset": 57344 },
        { "path": "firmware/tigerspool-v1.0.0.bin",     "offset": 65536 },
        { "path": "firmware/littlefs.bin",              "offset": 8454144 }
      ]
    }
  ]
}
```

> Offsets must match `firmware/partitions.csv`, and
> the filesystem offset above corresponds to the layout in
> [../docs/OTA.md](../docs/OTA.md). CI generates them from the partition table
> rather than trusting this example — **the values here are illustrative and will
> be regenerated.**

## What the page must do

**Say what is happening.** Erasing, writing, verifying, done — with progress.
A blank page during a 60-second write is where users pull the cable.

**Name the failure.** "No serial port found" needs to lead to the two real
causes: a data-capable USB cable, and a browser that is not Chrome or Edge.

**Offer the same languages as the firmware.** A user who cannot read the installer
cannot use the device.

**Erase on first install, preserve on update.** `new_install_prompt_erase` is
there so a returning user does not silently lose their Wi-Fi and their account.

## Layout

```
installer/
├── index.html      the page, with the ESP Web Tools button
├── manifest.json   generated by CI
├── locales/        translations, matching the firmware's
└── firmware/       built by CI, deployed to Pages — NEVER committed
```
